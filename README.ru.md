Юзерскрипт, который улучшает GitHub: полная панель настроек, командная палитра
по `Ctrl/⌘+K`, галерея изображений для отрендеренного markdown, цветные иконки
файлов везде, где GitHub показывает файлы, раскраска их возраста в стиле blame,
размеры файлов и скачивание в один клик, контекстное меню для действий с
файлами, быстрый просмотр любого файла и перевод текста прямо на странице.

> **Статус:** ранняя стадия (`0.22.0`). Панель настроек с мгновенным поиском
> (Общие · Галерея · Файлы · Перевод · Палитра · Резервная копия · О программе),
> командная палитра по `Ctrl/⌘+K`, галерея изображений markdown, цветные иконки
> файлов, раскраска возраста в стиле blame, размеры файлов и кнопки скачивания,
> контекстное меню файлов, быстрый просмотр файлов и перевод на странице.
> В планах — другие улучшения GitHub.

> `@updateURL` / `@downloadURL` скрипта указывают на ветку `main` в GitHub —
> ссылка для установки ниже всегда ведёт на самую свежую сборку.

## Быстрая установка

1. Установите менеджер юзерскриптов (рекомендуются
   [Tampermonkey](https://www.tampermonkey.net/),
   [Violentmonkey](https://violentmonkey.github.io/) или
   [ScriptCat](https://scriptcat.org/)).
2. Установите скрипт с GitHub (ссылка на raw-файл ниже).

**Ссылка для установки (GitHub — самая свежая):**

```
https://raw.githubusercontent.com/NemoKing1210/github-plus/main/github-plus.user.js
```

[![Install](https://img.shields.io/badge/Install-GitHub_raw-1f6feb?style=for-the-badge&labelColor=0d1117)](https://raw.githubusercontent.com/NemoKing1210/github-plus/main/github-plus.user.js)

### Установка по URL (в панели управления)

| Менеджер | Путь |
|---------|------|
| Tampermonkey | Панель управления → **Utilities** → **Install from URL** |
| Violentmonkey | Панель управления → **+** → **Install from URL** |
| Greasemonkey | Меню дополнения → **New User Script** → вставьте raw-URL |
| ScriptCat | Установите [расширение](https://scriptcat.org/), затем **Install from URL** с raw-URL GitHub |

### Ручная установка

1. Откройте собранный [`github-plus.user.js`](https://github.com/NemoKing1210/github-plus/blob/main/github-plus.user.js) в этом репозитории (или выполните `npm run build` после клонирования).
2. Скопируйте всё содержимое файла.
3. В менеджере юзерскриптов создайте новый скрипт и вставьте код.
4. Сохраните и включите скрипт.

## Обновления

Скрипт содержит метаданные `@updateURL` и `@downloadURL`, указывающие на
raw-файл в GitHub, поэтому поддерживаемые менеджеры обновляют его
автоматически.

Шаги релиза для мейнтейнеров: см.
[docs/DEVELOPMENT.md, раздел Releasing](docs/DEVELOPMENT.md#releasing).

## Возможности

### Галерея изображений для markdown

Каждый контейнер отрендеренного markdown на GitHub — это один набор галереи:

- **Клик по любому изображению** — в README репозитория, в просмотре
  `.md`-файла, на странице wiki, в issue, pull request, комментарии ревью
  (везде, где GitHub рендерит `.markdown-body`) или в отрендеренном markdown
  быстрого просмотра — открывает его на весь экран во встроенном просмотрщике.
- **Просмотр всего набора** — `←`/`→` (или стрелки на экране) переходят к
  другим изображениям того же контейнера, полоса миниатюр по центру позволяет
  перейти к любому, а счётчик показывает текущую позицию.
- **Масштаб и панорамирование** — колесо мыши, `+`/`−`, двойной клик и пинч
  увеличивают до заданного предела; перетаскивание двигает изображение при
  любом масштабе; `0` сбрасывает, `r` поворачивает; соседние изображения
  предзагружаются, поэтому листание происходит мгновенно.
- **Полный размер по запросу** — если изображение ссылается на файл большего
  размера (файл репозитория за страницей `/blob/`, загруженное вложение, любой
  URL изображения), этот файл проверяется и подставляется, так что вы получаете
  исходное разрешение, а если он недоступен, изображение не ломается.
- **Скачивание одним нажатием** — при наведении на изображение markdown
  появляется кнопка скачивания, а в панели просмотрщика есть своя; файл
  сохраняется под своим именем (прокси-адрес camo раскрывается до исходного
  имени файла), а одна настройка скрывает обе кнопки.
- **Ненавязчиво по умолчанию** — бейджи, статусные плашки, эмодзи и мелкие
  иконки никогда не занимают место в галерее; изображения сохраняют родной вид
  GitHub (курсор лишь подсказывает, что они открываются в галерее), а клики с
  модификаторами (Ctrl/Cmd/Shift/Alt) и средней кнопкой остаются за GitHub,
  поэтому открытие файла в новой вкладке работает как раньше.
- **Поддержка тем** — галерея и панель настроек используют переменные цветов
  GitHub, поэтому обе следуют выбранной теме (светлая, тёмная, dimmed).

### Иконки файлов

GitHub рисует каждый файл и папку одним и тем же серым глифом, поэтому `.ts` и
`.css` выглядят одинаково, пока не прочитаешь имя. GitHub Plus раскрашивает их:

- **Тип по расширению** — языки, конфигурации и форматы данных, изображения,
  медиа, архивы и документы получают собственную иконку; составные расширения
  вроде `.d.ts` и `.spec.ts` сопоставляются раньше базового.
- **Известные имена файлов** — `Dockerfile`, `package.json`, `README`,
  `.gitignore`, `tsconfig.json` и подобные получают отдельную иконку.
- **Роли папок** — `src`, `dist`, `node_modules`, `docs`, `.github`,
  `components`, `utils` и другие распространённые папки тоже помечаются.
- **Везде, где GitHub показывает файлы** — дерево репозитория и подпапки,
  боковое дерево файлов на страницах кода, заголовок файла на страницах blob,
  tree и blame, заголовки файлов в pull request и дерево диффа, списки файлов
  коммита, поиск по коду, gist'ы и ассеты релизов.
- **Ненавязчиво** — родной глиф GitHub скрывается и заменяется на месте; никаких
  изменений раскладки и лишних рамок, а отключение функции возвращает GitHub в
  исходный вид.

Иконки — курируемое подмножество
[Material Icon Theme](https://github.com/material-extensions/vscode-material-icon-theme)
(MIT); атрибуция в [THIRD_PARTY_LICENSES](THIRD_PARTY_LICENSES).

### Возраст файлов

GitHub уже показывает, как давно менялся каждый файл, но на первый взгляд все
даты выглядят одинаково. GitHub Plus берёт легенду blame и окрашивает сам текст
даты:

- **Один взгляд — и возраст понятен** — самые свежие даты тёплые (`#ffd78d` в
  тёмной теме, золотой акцент внимания в светлой), а старые блёкнут до
  приглушённого серого темы, поэтому файл четырёхмесячной давности уже выглядит
  старым. Шкала намеренно смещена к настоящему: дни, недели и месяцы различимы,
  а всё старше года — просто серое. У светлой и тёмной темы своя палитра, поэтому
  цвет остаётся насыщенным и читаемым в обеих.
- **Ничего не сдвигается** — дата сохраняет текст, относительную формулировку и
  подсказку GitHub; меняется только цвет, поэтому строки не перестраиваются, а
  доступная подпись остаётся ровно той, что отрисовал GitHub.
- **Файлы и папки** — строки папок тоже окрашиваются (дата означает их
  последнее изменение), а настройка позволяет ограничиться только файлами.
- **Ненавязчиво** — при отключении функции возвращается родной цвет даты GitHub
  и не остаётся никаких следов.

### Размер и скачивание файлов

В списке каталога GitHub показывает, когда файл менялся, но не его размер, а
чтобы сохранить файл, его сначала нужно открыть. GitHub Plus добавляет и то, и
другое прямо в строки файлов:

- **Размер сразу виден** — у каждого файла в списке репозитория появляется
  приглушённый размер в отдельном столбце. Размеры запрашиваются только для
  строк рядом с экраном, кэшируются на сессию, а если размер прочитать не
  удалось, он просто не показывается.
- **Скачивание на месте** — в каждой строке файла размер стоит у левого края
  столбца, а у правого — кнопка скачивания в стиле иконок-кнопок GitHub.
  Файл сохраняется под своим именем; raw-маршрут того же origin поддерживает и
  приватные репозитории, а при заблокированном запросе файл открывается в новой
  вкладке. На странице самого файла GitHub уже показывает размер и кнопку
  скачивания, поэтому она не меняется.
- **Без лимита API** — размер берётся HEAD-запросом по raw-адресу самого файла,
  а не через GitHub API, поэтому анонимный лимит в 60 запросов в час не
  расходуется.
- **Ненавязчиво** — у папок столбец остаётся пустым, а при отключении функции
  исчезают все размеры, кнопки и ячейки, и страница возвращается к обычному
  GitHub.

### Контекстное меню файлов

Правый клик по файлу — самый быстрый путь к действию, но в меню самого GitHub
нужных пунктов нет. GitHub Plus заменяет его для файлов:

- **Быстрые действия** — правый клик по файлу в списке репозитория, в боковом
  дереве файлов или по ссылке на файл в отрендеренном markdown открывает
  **Открыть**, **Открыть в новой вкладке**,
  **Скачать**, **Скопировать содержимое**, **Скопировать ссылку** и
  **Скопировать путь**. На странице файла или blame появляется то же меню (без
  **Открыть**, вы уже там).
- **Копировать содержимое** — текст файла попадает в буфер обмена без открытия
  страницы; для двоичных файлов и файлов больше 1 МиБ вместо этого выводится
  понятное уведомление, чтобы не вставлять мусор и не подвешивать вкладку.
- **Копировать путь** — путь относительно репозитория (`src/main.js`), готовый
  для терминала, импорта или ссылки.
- **Только там, где это полезно** — для папок, изображений, медиа и обычных
  ссылок (включая markdown-ссылки, которые не ведут к файлу репозитория) родное
  меню не трогается; правый клик не по файлу ведёт себя как раньше.
- **С клавиатуры тоже** — клавиша контекстного меню открывает то же меню у
  ссылки на файл, с навигацией стрелками и возвратом фокуса после закрытия;
  отключение функции возвращает обычное меню везде.

### Быстрый просмотр файлов

Любой файл можно открыть, не покидая страницу — кнопкой-глазом в списке файлов,
ссылкой на файл в отрендеренном markdown или через **Просмотр** в контекстном
меню файла:

- **Отрендерено, а не в исходнике** — markdown отображается и очищается,
  исходники получают подсветку синтаксиса и номера строк, изображения, видео и
  аудио воспроизводятся на месте, а PDF открывается во встроенном просмотрщике
  браузера, если политика страницы GitHub разрешает встроенную рамку. Всё
  остальное — включая PDF, который страница блокирует, — показывает честную
  карточку с **Открыть на GitHub** и **Скачать** вместо сломанной рамки.
- **Переход по папке** — файлы одного каталога образуют набор: кнопки
  «назад/вперёд» и стрелки клавиатуры переключают их, а внизу показана текущая
  позиция.
- **Просмотр по удержанию** — зажмите левую кнопку мыши на названии файла в
  списке или на ссылке на файл в отрендеренном markdown (в том числе уже
  открытом в быстром просмотре), чтобы открыть его просмотр; время удержания
  (по умолчанию 450 мс) и круг заполнения у курсора настраиваются; обычный клик
  по-прежнему открывает файл, а перетаскивание и выделение текста отменяют жест.
- **Действия в шапке** — открыть файл на GitHub, скопировать его исходное
  содержимое, ссылку или путь, либо скачать под собственным именем.
- **Markdown: просмотр или исходник** — сегментированный переключатель
  показывает отрендеренный markdown или его исходный текст с подсветкой
  markdown.
- **Безопасно с приватными репозиториями** — относительные изображения и ссылки
  идут через тот же origin по raw-маршруту, поэтому приватный README сохраняет
  картинки; markdown очищается, а внешние изображения загружаются без referrer.
- **Честные ограничения** — текст и markdown до 2 МиБ, PDF до 25 МиБ, а
  подсветка ограничена, чтобы огромный файл не подвесил вкладку; сверх лимита
  карточка ведёт на GitHub и исходный файл.

### Перевод

Переводите текст страницы, не теряя разметку — README, issue или обсуждение,
pull request, комментарий, сообщения коммитов, заголовок или markdown-файл в
быстром просмотре:

- **Кнопка там, где живёт текст** — в заголовке файла README, в строке действий
  комментария, у коммита или заголовка issue. Если у GitHub нет заголовка, над
  текстом появляется небольшая панель.
- **Разметка сохраняется** — ссылки, изображения, строчный код, чекбоксы задач
  и выделение продолжают работать: перевод заменяет текстовые блоки, а не
  структуру вокруг них.
- **По кнопке или автоматически** — по умолчанию ничего не отправляется, пока вы
  не нажмёте кнопку; в автоматическом режиме блок переводится при появлении на
  экране, а кнопка **Показать оригинал** остаётся.
- **На месте или под оригиналом** — замените исходный текст или покажите перевод
  под ним; **Показать оригинал** возвращает точный текст, а показ при наведении
  позволяет заглянуть в оригинал, пока курсор или фокус внутри блока.
- **И текстовые файлы** — файлы лицензий и уведомлений (LICENSE, COPYING),
  показанные как код, получают ту же кнопку; перевод появляется под файлом, а сам
  код никогда не переписывается.
- **Шесть провайдеров** — бесплатный Google по умолчанию (без ключа,
  неофициальный и с ограничением частоты), а также DeepL, Microsoft, Yandex,
  совместимый с OpenAI эндпоинт или ваш экземпляр LibreTranslate. Переводимый
  текст отправляется выбранному сервису; API-ключи остаются в этом браузере,
  поэтому резервная копия настроек содержит их.
- **Кеш** — перевод используется повторно 24 часа по умолчанию (настраивается;
  0 отключает кеш) и очищается на странице настроек.

### Командная палитра

Нажмите `Ctrl/⌘+K` на любой странице GitHub — откроется одно поле поиска по
всему, что вы там делаете:

- **Из шапки** — кнопка палитры рядом с действиями в шапке GitHub открывает её
  с любой страницы и показывает текущее сочетание клавиш.
- **Ваши репозитории** — все репозитории, которыми вы владеете; свои идут
  первыми, а звёзды, язык, время последнего push и видимость показаны в панели
  деталей. Введите `@`, чтобы искать только репозитории.
- **Репозитории со звёздами** — проекты, к которым вы возвращаетесь: они идут
  после ваших и отмечены звездой.
- **Файлы текущего репозитория** — `#` показывает все пути текущего репозитория
  (или запрос, совпадающий с ними); файл открывается на GitHub на той ревизии,
  которую вы просматриваете.
- **Открытые issues и pull request'ы** — открытые issues и pull request'ы
  текущего репозитория с отметкой issue или pull request; в панели деталей
  видны автор, время обновления и число комментариев. Ищите по заголовку,
  номеру или автору.
- **Страницы GitHub и действия GitHub Plus** — откройте свои issues, pull
  request'ы, уведомления или настройки; откройте панель GitHub Plus; переключите
  её функции; обновите кеш. `>` ограничивает список командами, `?` отправляет
  запрос в собственный поиск GitHub.
- **Избранное и недавнее** — закрепите то, чем пользуетесь постоянно
  (`Alt+P`); закреплённые строки отмечены звездой и идут первыми — и в пустом
  списке, и в результатах поиска. Недавно открытые строки возвращаются наверх
  при следующем открытии — отдельно для каждого аккаунта GitHub.
- **Действия со строкой** — щёлкните строку правой кнопкой, нажмите
  `Shift+F10` или кнопку `⋯`, чтобы открыть её, открыть в новой вкладке,
  скопировать ссылку, путь, адрес для клонирования или номер issue, а также
  закрепить или открепить её.
- **Быстро и тихо** — палитра мгновенно показывает кешированный список,
  обновляет его в фоне и сохраняет выбранную строку. Результаты кешируются с
  ETag на сессию и между перезагрузками, поэтому палитра не тратит лимит API;
  без токена она читает публичные данные, и все команды всё равно работают.
- **Необязательный токен GitHub** — добавьте его на странице настроек палитры,
  чтобы видеть приватные репозитории и полные списки (5 000 запросов в час
  вместо 60). Токен проверяется перед использованием, хранится только в этом
  браузере, никогда не попадает в резервную копию и отправляется только на
  `api.github.com`; кеш ведётся отдельно для каждого аккаунта, поэтому при смене
  аккаунта чужие репозитории не показываются.
- **Сначала клавиатура** — `↑`/`↓` двигают выбор, `Enter` открывает,
  `Ctrl/⌘+Enter` открывает в новой вкладке, `Alt+P` закрепляет, `Esc` очищает
  запрос, а затем закрывает палитру; в редакторе комментария или README палитра
  не мешает, а при навигации закрывается сама. Сочетание клавиш — это готовый
  вариант или любая комбинация, записанная на странице настроек палитры.

### Панель настроек

Откройте её кнопкой с шестерёнкой в шапке GitHub, строкой **Настройки GitHub Plus**
в меню аватара (сразу под собственным пунктом **Settings** GitHub) или командой
меню в менеджере юзерскриптов. Изменения черновые: ничего не сохраняется, пока
вы не нажмёте «Сохранить»; «Отмена», клик по подложке и `Escape` отбрасывают
черновик; «Сбросить по умолчанию» сначала просит подтверждение.

## Как устроена галерея

Галерея — это небольшой фреймворк плюс один источник на каждое место, где
живут изображения, поэтому добавление нового места не затрагивает саму
галерею:

| Файл | Роль |
|------|------|
| `src/ui/viewer.js` | Лайтбокс: `openViewer({ images, index, loop, thumbnails, download, minZoom, maxZoom, resolveImage, labels, onClose })`, а также `closeViewer()` / `isViewerOpen()`. Самодостаточен — может использоваться любой функцией. |
| `src/gallery/sources.js` | Реестр источников: `registerSource`, `listSources`. |
| `src/gallery/collect.js` | Сбор: нормализация, фильтрация (бейджи/эмодзи/мелкие иконки), дедупликация, ограничение количества. |
| `src/gallery/index.js` | Связывание: один слушатель кликов в фазе перехвата, сгенерированная таблица стилей курсора, делегированные слушатели наведения для кнопки скачивания, слушатель настроек. |
| `src/gallery/sources/markdown.js` | Источник markdown: контейнеры, поиск изображений, определение полного размера. |

Поскольку индикатор — это CSS, построенный из реестра, а обработка кликов —
один делегированный слушатель, обходящий живой DOM, галерея продолжает
работать после клиентской навигации GitHub и ре-рендеров React без цикла
сканирования и поштучного учёта изображений.

### Добавление источника

```js
import { registerSource } from '../sources.js';

registerSource({
  id: 'mySurface',            // also the settings switch key (gallery.sources.mySurface)
  labelKey: 'source.mySurface',
  hintKey: 'source.mySurfaceDesc',
  containerSelector: '.my-surface',   // one container = one gallery set
  cursorSelector: '.my-surface img',  // gets cursor: zoom-in while enabled
  collect(container) {
    // return [{ node, src, alt?, title?, href? }]
  },
  resolveFull(item) {
    // return the best full-size URL for item, or '' when unknown
  },
});
```

Затем добавьте переключатели в четыре места одновременно: модуль источника +
его импорт, `DEFAULT_GALLERY.sources.<id>` в `src/core/constants.js` и ключи
`source.<id>` / `source.<id>Desc` во **всех десяти** файлах
`src/i18n/locales/*.js`. Панель настроек подхватывает новый источник из реестра
автоматически.

## Разработка

Требуется Node.js 22 (см. `.nvmrc`).

```bash
npm install
npm run dev                # vite-plugin-monkey dev server (dev: prefix)
npm run build              # vite build + copy dist/ → root artifacts
npm run verify:artifacts   # fail if dist/ and root artifacts differ
npm run ci                 # build + verify (CI gate)
npm run icons:build        # regenerate the embedded icon subset
npm test                   # Node test runner (unit tests)
```

Редактируйте только файлы в `src/` — `github-plus.user.js` и
`github-plus.meta.js` генерируются. См. [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)
для тестирования и отладки, [CONTRIBUTING.md](CONTRIBUTING.md) для правил,
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) для карты модулей и потоков данных
и [DESIGN.md](DESIGN.md) перед изменением любых видимых элементов.
